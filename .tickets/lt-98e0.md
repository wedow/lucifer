# native unit-to-unit calls: the callee's frame record in its machine frame, borrowed arguments

A direct call from one unit to another costs about 280 machine instructions end to end, not counting the callee's body (luc-ne54: caller about 150, entry stub about 109, callee 24), and the callee releases its parameters at return (1.26% of all steady-state cycles over 14 programs; the call protocol as a whole is 8.6%). Target: under about 30 instructions for a leaf callee and about 50 for one that publishes, by treating the callee's activation as an inlined frame is treated. Stages S1 to S4 below land separately, each test first, each with an adversarial review (reference counts, frames, invalidation). Before S2 is built, confirm with a test on master whether a parameter rebound or deleted inside a callee that is not inlined releases its object during the call today; if it does, S2's delay of that release to the call's end widens the temporaries concession and is the owner's decision. S5 is not approved.


## Design (2026-11-24)


Paths are relative to the repository root at 48e3e494. Written from reading the code; nothing was built or run. A claim that is inference rather than something read is marked "inferred".

## 0. Summary

A direct call costs about 280 instructions today because of four things:
- the callee gets a full interpreter frame on the datastack, with code and func counted;
- every parameter is counted twice: increfed by the entry stub or taken from the caller's holds, then given back;
- every call re-runs the interpreter's checks, even when the callee is a compile-time constant;
- the caller undoes all of it on return.

The proposal follows `docs/design/jit-architecture.md` §4.4 ("a machine frame that begins with the leading fields of struct lu_frame … It has no locals array"), with one change: the record does get room for the locals.

- **The callee's frame record (call it the NAR, native activation record) is an ordinary `struct lu_frame` placed in the callee unit's own machine frame**, with `co_framesize` words of room. It is never put on the datastack.
  - Walkers, `lu_jit_sync`, frame objects and exits use it exactly as they use a compiled root today.
  - When the interpreter must take over, it runs that record in place, nested, as `lu_jit_call_finish` already does.
- **Arguments are borrowed.** The callee reads its parameters from the caller's argument area. The caller's operand references outlive the call.
- **A statically known callee is reached through a per-key cell** (`call [cell]`). Death, tools, an eval hook or a version change swap the cell to a generic adapter, so the per-call checks go away.
- **A callee with no instruction that publishes (a "leaf") writes no record at all.** Its exits and cold parked paths fill and link the record on demand.

Estimated end state: about 25–31 instructions for a two-argument leaf call, about 50 for a non-leaf callee. The non-leaf extra is the record and its link.

## 1. How it works today

### Frame record
- `struct lu_frame` (`runtime/interp/frame.h:52-76`): code (strong), previous, func (strong), globals, builtins, locals, frame_obj, instr, last, stackpointer, owner, ret and home bytes, jit_desc, jit_spills, jit_regs, jit_forced, then `localsplus[]`.
- `LU_FRAME_JIT` means compiled code owns the slots (`frame.h:23`).
- Frames are bump-allocated on the datastack (`frame.c:41-68` `alloc_frame`; `frame.c:72-85` `free_frame`; `lu_frame_pop` at `frame.c:205-212`). `lu_frame_pop` decrefs code and clears func.

### Unit prologue and epilogue
- `prologue` (`x86_64/emit.c:5321-5341`) puts the task in R14 and the frame in R15 and stores RESULT_SLOT. It sets `stackpointer = localsplus` (slots hold nothing), swaps owner into home, sets owner to JIT, and sets `jit_spills = rbp + SPILL_BASE`.
- The machine frame layout is at `emit.c:5-14` and `51-56`: CALL_SLOT holds the `struct lu_jit_call` of a direct call in progress.
- `OP_RETURN` (`emit.c:5262-5270`) stores through RESULT_SLOT, restores owner and returns `LU_JIT_RETURN`.
- `OP_UNLINK` (`emit.c:5218-5238`) sets `current_frame = previous`.
- Parameters are `OP_ENTRY_LOCAL` loads from `[r15+localsplus]` (`emit.c:3952-3955`) and are owned (`eval_flow.c:2170` `lu_ev_own`), so the unit releases them at return.
- `GUARD_DEPTH` and `GUARD_ENTRY` are emitted at entry (`eval_flow.c:2184-2192`; `emit.c:4393-4411`).

### Direct entry stub
`direct_entry` (`emit.c:5370-5563`) runs these steps in order:
1. saves;
2. serial `unlocked_jit` (5377-5381);
3. dead (5382);
4. globals and builtins against the unit's key (5384-5391);
5. C stack floor (5392-5394);
6. poll word against the compiled instrumentation version (5396-5399);
7. `_co_monitoring` (5400-5402);
8. `ts->tracing` (5403-5404);
9. PEP 523 hook other than perf's (5406-5413);
10. recursion or kernel_room (5414-5422);
11. datastack room (5423-5429);
12. frame push and depth (5431-5439);
13. activation link into the caller's `struct lu_jit_call` and `task->jit_act` (5440-5446);
14. frame fields plus `incref` of code and func (5447-5468);
15. parameters, incref unless the R8 `takes` bit is set (5470-5484);
16. prologue cells in C, or `COPY_FREE_VARS` in line (5485-5529);
17. entries counter and grow (5531-5545);
18. stats (5546-5553);
19. jump to `entered`.

It exists only when `lu_jit_direct_nargs >= 0` (`jit.c:320-327`: plain positional, no generators) and the unit is at the call entry (`emit.c:5724`).

### Caller side
- `call_helper` (`emit.c:2052-2103`) stores the variadic argv at `[rsp]` (callable, self, args).
- For `H_call` it emits `call_direct` (`2011-2048`), which checks the PyFunction or PyMethod type, then calls `direct_call` (`1973-2004`): `co_executors` tag, `nargs`, entry word, the call, and the declined branch.
- `direct_done` (`1901-1966`) does: unlink act and serial restore (1904-1912), stale check and `lu_jit_left` (1913-1918), RETURN compare (1919-1922), frame_obj and `lu_frame_retire` (1923-1927), `lu_depth_leave` (1929-1940), DECREF of func and code (1944-1949), datastack_top (1950-1951), `takes_back` (1952). Anything other than RETURN goes to `lu_jit_call_finish` (`helpers.c:1047-1062`), which runs the interpreter nested behind a C-entry marker.
- `publish` and `unpublish` (`emit.c:1796-1872`): the desc address goes into `jit_desc`, inlined frames are counted only across the call (`depth_add`), and holds are taken (`holds_of` 1677-1708, `takes_of` 1715-1744: the arguments whose stack-entry holds the callee's parameters take).
- `settle` / `GUARD_FRAMES` after the call (`2117-2126`; `4412-4446`): owner still JIT, unit not dead, and at a root's return (imm 1) no frame object held by anyone else.

### C entry paths
- `lu_jit_enter` is the interpreter's entry (`jit.c:1278-1340`).
- `lu_jit_run` is C with a pushed frame (`1392-1474`).
- `lu_jit_direct` is C with an args array (`1477-1510`), called from `helpers.c:985` `call_function` (which owns the `takes` dance at 959-1022) and from `object/function.c:95-100` `function_vectorcall`.
- `jc->direct` is one entry word per code (`jit.c:101`). `kill` CASes it to NULL (`1040-1045`); compile publishes it (`1220-1229`).

### Description and materialization
- `struct lu_deopt` (`target.h:129-151`) holds frame records, owned, takes, regs and visible.
- `struct lu_deopt_frame` (`103-114`) chains inlined frames by `caller`.
- `exit.c`:
  - `lu_jit_deopt` (`658-745`) fills the root's slots in place and pushes inlined frames on the datastack (`push_inlined` 616-655, moving walker records). Owned references are released last.
  - Walkers: `lu_jit_sync` / `sync_root` (`409-439`) give the root real slots in place and set owner back to home. `lu_jit_force` (`566-610`) builds calloc'd records for inlined frames linked above the root, keeps them in `root->jit_forced`, and moves `ts->current_frame` to the top record.
  - The unit sees owner != JIT at its next `GUARD_FRAMES` and leaves.

### Nesting
- Every compiled activation's root is a real frame on the `current_frame` chain.
- `seen()` and `lu_frame_walk` (`frame.c:267-299`) force each JIT root as the walk reaches it and patch the record above it via `above->previous`.
- `lu_frame_current` forces with `all` (`frame.c:302-309`).
- For reclaim, activations are listed by `task->jit_act` (`target.h:291-295`). `lu_jit_reclaim` (`jit.c:767-807`) marks held units with the world stopped. `left()` (`838-844`) releases stale units.

### Helpers that assume the running root is `ts->current_frame`
- `taken_args` (`helpers.c:963-967`), `raised_arm_ok` (`263-273`, which also reads `t->jit_act->unit`), `h_exc_here` (`293-301`).
- Inlined calls poll at their RESUME (`eval_ops.c:463-468`, POLL_CALL).
- `OP_POLL` costs 3 instructions on the fast path (`emit.c:5128-5195`).

## 3. The lazy-frame scheme

### 3.1 Native convention
- R14 holds the task on entry and is preserved. RSI is the function (borrowed), RDX the argument array (borrowed, one word per bound parameter in frame order). RAX returns an owned value, or NULL with the exception set.
- RBX, R12, R13, R15 and RBP are preserved (C ABI).
- C callers (`lu_jit_direct`, the adapter path) use a shared thunk: push r14, set r14, call, pop.
- The caller emits:

  ```
  mov rsi, fn            ; or the funcv register
  lea rdx, [rsp+16]      ; +8 when self is argument 0, as direct_call's off
  publish                ; caller's desc, plus holds on non-operand slots
  mov r11, cell
  call [r11]
  unpublish
  test rax, rax
  jz error
  ```

- **Cell.** One per key (code, globals, builtins), owned by the code's JIT state, with a stable address that the static caller embeds.
  - It points to the live unit's native entry, or to `lu_jit_native_generic`.
  - The generic adapter (C) pushes a datastack frame, increfs the arguments into it and runs `lu_eval` (which counts hotness and enters a frame-mode unit). Because of the adapter there is no "declined" branch in the caller.
  - Compile publishes into the cell with the same store-then-check-dead order as `jit.c:1220-1229`. `kill` swaps it back (`jit.c:1040-1045`, per key instead of per code).
  - The caller's unit holds the callee's code as a constant (`lu_ev_konst`), so `f.__code__ = other` during f's run cannot free the code under its unit.
  - Not verified: whether anything other than `func_set_code` can drop the last code reference while a call runs. C callers incref the code around the thunk.

### 3.2 The record (NAR)
- A `struct lu_frame` at a fixed offset below rbp in the callee's machine frame, with room for `co_framesize` words. It is stack space only and costs nothing to reserve.
- New field: a `native` byte in the padding after `home` (`frame.h:65`). It means: not on the datastack, and code/func are borrowed.
- **Non-leaf units** (any instruction for which `lu_publishes` is true) fill it eagerly at entry:
  - `previous = ts->current_frame`, `current_frame = NAR`;
  - code, func, globals/builtins (unit constants), locals = frame_obj = 0;
  - owner, ret, home and native in one dword;
  - jit_desc = jit_forced = 0;
  - `jit_spills` derived (rbp-relative) or stored.

  `OP_UNLINK` already exists in their return path. It is then an ordinary compiled root for every reader: `seen`/`lu_jit_force`, `lu_jit_sync` (in place, since there is room), `lu_frame_object`, `h_exc_here`, `raised_arm_ok` (change it to read the unit from `current_frame->jit_desc->unit` instead of `t->jit_act`), and `instrument_all_executing_code_objects` (`instrument.c:1282`).
- **Leaf units** set `R15 = NAR` (they push and pop r15) and write nothing. Nothing can reach them except their own exits and cold parked paths (poll in place, a parked `LIST_ITEM`). Those first fill the record from the unit (code, globals, builtins), from func (saved in a slot at entry: 1 store), and from `ts->current_frame` (as previous), then link it. A parked path unlinks it again afterwards. With no published call, `GUARD_FRAMES(imm 1)` can be dropped in call-entry units: extend `facts.c:94-130`, which today drops only imm 0.
- **Exits** (`lu_jit_deopt`, `exit.c:658`) see `root->native`:
  - complete and link the record if it is a leaf's, incref code and func, take the depth if it was only checked, and fill the slots in place exactly as today;
  - push inlined frames on the datastack above it, call `lu_jit_call_finish` nested (the interpreter runs the record in place; it returns into the C-entry marker), and return the value through the unit's epilogue in RAX.
  - `lu_frame_pop` and `free_frame` skip the datastack for `native` frames.

  So a deopt in the callee materializes only the callee's frames. The caller stays compiled and receives a value or NULL, as it does after `h_call` today. Callers are materialized only if a walker forces them, and then they leave at their own `GUARD_FRAMES` after the call (existing behaviour).
- **Frame-mode entries** (`lu_jit_enter` at the call entry, `lu_jit_run`) use the same body.
  - A small frame stub sets R15 to the real frame F and RDX to an anchor array of F's parameters, which C moves out of F and decrefs after the unit returns or leaves. `GUARD_ENTRY` moves from the body into this stub (the native entry needs no key check).
  - Call-entry units return a value or sentinel in RAX; the frame-mode C maps it back to `enum lu_jit_result`. Loop-entry units keep today's protocol.
  - Call entries that are also jump targets (`eval_flow.c:2158-2165`) keep frame mode only.

### 3.3 Hazards

**Walkers and the chain.**
- Non-leaf records are on the chain. Leaves are linked whenever anything can look.
- The caller's desc is published during the call, so `lu_jit_force` on the caller works unchanged.
- Forced records of a NAR's inlined frames live in `NAR->jit_forced` and move at its exit.
- Signal-time walkers: faulthandler reads its own chain (`faulthandler.c:144`). A non-leaf NAR with `jit_desc == 0` shows its function's first line.
- Fix `PyUnstable_Object_IsUniqueReferencedTemporary` (`object/refcount.c:382-393`): it reads `stackpointer` without checking owner; it should return 0 for JIT frames.

**Exceptions.**
- An error exit in the callee materializes, the nested interpreter unwinds the callee with correct traceback lines, and NULL comes back to the caller. From there the caller's handler or error exit takes it (`h_exc_here` and the rest of stage 2a, as for `h_call`).
- Kernel roots return NULL for `LU_JIT_RAISED`.

**Generators and coroutines are excluded.** A call only makes the generator (`lu_jit_new_gen`). Resumes need a frame that survives suspension, so no machine-frame record. This is already excluded by `lu_jit_direct_nargs`.

**Cells.** Codes with `CO_FAST_CELL` are excluded first: `MAKE_CELL` may raise and runs in C (`emit.c:5489-5507`). Free variables come next: borrowed loads of `func->func_closure` items.

**Recursion and the C stack.**
- Depth is exact, as above.
- Native nesting costs C stack per level. Non-leaves check the limit word. When it is exceeded the cell's slow path enters through the generic adapter, whose interpreter frames do not nest C. This is today's "declines" behaviour.

**Tools switched on mid-call.**
- `set_global_version` (world stopped) swaps every cell to the generic adapter, through a registry of cells, and kills units.
- Running activations leave at their next poll or published check, as today.
- `set_local_events` and code instrumentation swap that code's cells.
- `_PyInterpreterState_SetEvalFrameFunc` swaps all cells (perf's hook excluded, as today).
- The tools see the next call from its RESUME.

**Frame objects escaping.**
- A frame object of a non-leaf NAR reads through the record while it runs.
- At return, `GUARD_FRAMES(1)` leaves if anyone else holds it. The interpreter then returns from the record in place and `lu_frame_retire` copies the locals into the frame object.
- If only the record holds it, it is dropped. `f_back` is `previous`.
- The logging case (`findCaller` making frame objects of callers) therefore does not deopt non-leaf NARs, because they are linked.

**Collector.**
- Reachability comes from counts and stacks are never scanned (`collector.c:17-20`). Borrowed arguments are counted by the caller's reference.
- Record slots hold nothing until a sync or exit fills them with counted references.
- `frame_traverse` does not visit live frames (`frame.c:479-498`).

**Signals and the periodic poll.**
- Non-leaf entry checks one limit word: the stack floor, or UINTPTR_MAX while any poll event is posted. The poster sets the event, then the limit; the clearer re-reads the poll word after restoring the limit.
- Leaves do bounded work. Loops inside them poll as they do now.

**Handoff scheduler.** It migrates only at polls with no compiled code pinned below, and the nested interpreter in `lu_jit_call_finish` pins (`helpers.c:1058`). Unchanged.

**Serial to parallel.**
- Serial callers keep `unlocked_pause` around the native call (`emit.c:2061`).
- Serial callees keep "store 1, then read dead, restore at return", about 6 instructions, in their native entry only.
- Skipping both when caller and callee are both serial is S5, through a second cell word.

**Invalidation and freeing.**
- Kill swaps the cell. Running activations leave at their checks.
- `lu_jit_reclaim` additionally walks each stopped task's frame chain and marks `jit_desc->unit` for `native` JIT frames. When the world is stopped every native activation is linked and published: the innermost is at a published call or a parked poll, and the outer ones are in native calls. So `free_unit` (`jit.c:682`) runs only after the last such activation has ended.
- `left()` is not called on native returns. A stale unit is freed at the next reclaim, unless the unit has dict dependencies, in which case its return checks `stale` (3 instructions). See question 5.

## 4. Borrowed arguments

**When borrowing is safe.** The caller's reference outlives the call, because a call's operands stay held until the instruction ends (`architecture.md` §10). The caller cannot rebind its slot except through frame access. That forces the caller's frames (`sync_root` gives every slot its own reference through `take`, `exit.c:274-294`), while the caller's compiled reference stays in `d->owned` until its exit after the call. Nothing more is needed for each slot to have its own count.

**What the callee does with a parameter.**
- **Not owned:** `ENTRY_LOCAL` is no longer wrapped in `lu_ev_own` for call-entry units (`eval_flow.c:2170`).
- **Store into the heap:** gets its own reference, as for any borrowed value.
- **Rebind:** releases nothing.
- **Return:** `lu_ev_return` retains a value it does not own (`eval_call.c:713-719`).
- **`del x` / rebinding with a finalizer:** the finalizer runs after the call returns. This is the existing concession for temporaries in `architecture.md` §10.

**Holds.**
- At a static native call the caller excludes the call's own operand entries (callable, self, args) from `holds_of`; they move into the callee.
- The callee's published calls hold its unowned parameters (n=1 per name, `emit.c:1634`), so C sees caller reference + callee parameter, exactly as in CPython.
- Other caller slots that name the object are still held at the native call's publish.

**Own on demand.** A parameter handed to any published call is increfed at entry and released at return, so a method passing `self` to several helpers does not pay a hold at each one (luc-ne54 measured about 23 instructions per hold).

**What gets deleted.** `takes` disappears (`lu_deopt.takes`, `takes_of`, `takes_back`, `taken_args`, `call_function`'s `takes`, and `lu_jit_direct`'s give-back).

**Dynamic sites.** On the native path of a dynamic `H_call`, the operand holds are given back before entering, to keep counts exact. C callees keep them.

**Borrow pass.** A native call is `FX_PY`, so it is not `borrow_safe`. Borrowed web members cannot be its operands or live across it (`opt.c:452-466`), so an uncounted list item is counted before it is passed. Borrowed parameters are good anchors for the callee's own borrowed item reads, since they are never released. `ENTRY_BORROW` (loop entries) is unaffected. Leaf summaries could make calls to leaves `borrow_safe` only once a summary says the leaf "frees nothing it does not own" (S5).

## 5. Which callees, fallback, methods and keywords

**First qualifiers:**
- the callee is known at compile time and not inlined: a constant `kc`, or `funcv` with the code as a constant (`eval_call.c:106-159`, `75-96`);
- `CO_OPTIMIZED`, not `LU_CO_GENERATORS` or `CO_ITERABLE_COROUTINE`, no cell variables;
- the call entry is not a jump target;
- user or kernel code (kernel uses `kernel_room` instead of `rr`).

Defaults, keyword-only, `*args` and `**kwargs` are bound by the caller (`bind`, `call_bound` at `eval_call.c:611-654`). The native entry takes every parameter in frame order, and `*args`/`**kwargs` are real objects the caller made and keeps.

**Methods.**
- Method-form self is argument 0.
- A bound method object is guarded on `im_func`, with self loaded (`eval_call.c:142-148`).
- Keyword calls go through `call_bound`.
- All of these reach the same native entry through the same cell.

**Fallback.** When there is no unit yet, or the unit dies, the cell points at the generic adapter. No patching of call sites.

**Dynamic `H_call` sites.** They keep a short dispatch: type test, `func->jit_cell` (a word cached in the function's padding, as `lu_jit_calls` already is), arity, `call [cell]`.

## 6. Stages

Each stage passes `tools/floor quick` and writes its test first.

### S1 — bound entry for static callees (largest share, safe alone)

- **Change.**
  - New lowering for a known callee: a per-key cell, and an entry that skips the dynamic checks.

## 7. Open questions

1. Can `ts->tracing` be nonzero with no tool active? If so, the cell swap does not cover it.
2. Does any C path besides `free_frame` assume a frame lies on the datastack: pointer comparisons with `datastack_top`, chunk walks, generator start (`gen.c:222`, `600`)?
3. Codes reached only through native cells: does `set_global_version` together with the interpreter's lazy instrumentation at RESUME instrument them once the cells are swapped? Today `instrument_all_executing_code_objects` sees only roots on the chain; inlined codes are already missed.
4. Does a serial unit killed by the switch always leave at its next poll, so the switch cannot wait forever on a spin loop? This only matters for S5.
5. Is freeing stale units at the next reclaim, instead of at the last activation's end, acceptable? Or should units with dict dependencies keep the 3-instruction check at return?
6. Under S5, counts inside a callee for objects named by other caller slots read one lower. Does that fall under concession 1?
7. A callee that deopts at every level of a deep recursion nests one interpreter activation per level, as `lu_jit_call_finish` does today. Acceptable?
8. Can a call-entry frame ever have a frame object before its unit runs? If yes, the `GUARD_FRAMES(1)` elision for leaves is unsafe.
9. Does `ENTRY_LOCAL` emission keep RDX live up to the last parameter load (they come first at `eval_flow.c:2166-2172`), or should the argument base go in a frame slot?
10. Creating a per-key cell at the caller's compile gives the callee code JIT state, which makes `lu_jit_call_hot` compile it on its next interpreted call. Is that intended?
11. With the perf hook (`-X perf`), native entries start mid-unit, as `direct_entry` does today. Is perf's map and CFI still right?
