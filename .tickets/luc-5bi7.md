# jit: reference counts out of compiled code (borrowed reads, paired counts removed, numbers without a kept box)

Measured: DECREF and INCREF are 6.7% of real-program steady state as IR instructions alone, before the counts inside LIST_ITEM, the stores and the release calls (_Py_Dealloc and the per-type deallocs another ~4%). In for v in xs: s += v the item is counted up when read and down one iteration later only so its box can be handed back if the int is ever needed as an object.

Mechanisms: (1) a value read from a container or attribute and used only until the next instruction that can run arbitrary code or switch tasks is borrowed, not counted (frees deferred past the next poll already exist for readers without the lock); (2) a count up and its matching count down with nothing between them that can observe the count cancel; (3) an unboxed int or float does not keep the object it was read from: ints in the small cache are immortal singletons already, and the owner-approved concession on re-boxed identity covers the rest only for attribute stores, so widening it is an owner decision to raise with numbers.

Acceptance: idiom rows list sum, tuple unpack, linked-list walk, read-4-attributes; DECREF+INCREF share on the 14 profiled pyperformance rows halved.

How the pass works (runtime/jit/opt.c borrow_items, before lu_ssa_facts, only while serial): webs are union-find classes of READ values (LIST_ITEM+, or a tuple-unpack LOAD+ marked LU_LOAD_TUPLE_ITEM with its one INCREF) and the owned phis joined through their inputs; inputs may be constants (NO_COUNT, which need no liveness: the unit keeps them) or the entry block's owned ENTRY_LOCAL/ENTRY_STACK (ENTRY_COUNT). An entry value stays in its web only with a named holder (entry_read): a read of the web whose container is an entry-block value and whose index is a phi starting from a constant (the holder is the container's last item: the loop ran to its end before the entry) or from an entry-block index (the item before it); for a tuple item, the tuple's LIST_ITEM must itself go uncounted so that its container is on the chain. ENTRY_BORROW checks identity at the entry (every check before any release), stands for the value in the web's phis, then DECREF #0 releases the entry reference, which no later state names. Its failures are guard failures at the entry pc and mark NOBORROW there (jit.c), after which the rebuild keeps such webs counted. borrow_round computes member liveness to a fixpoint (frame states are uses) and spoils every web live across an instruction outside borrow_safe (a LIST_ITEM is safe only if it goes uncounted), or whose container chain (on_chain) is released in range; POLLs and INLINE_LOADs with members live across get INS_LEAVES (the flags word is 16 bits since; imm2 of the inline loads is the field-kind work's). LUCIFER_JIT_DEBUG=1 prints 'jit: borrow:' lines saying why each web stayed counted or which entry was borrowed.

Invariants (re-derived 2026-11-24):
- B1. A value held without a count is a LIST_ITEM or tuple item read in its serial form, a phi of such reads and constants, or an entry value ENTRY_BORROW proved to be its holder's item; each has a container on its web's chain that the unit holds or that a member on the chain holds.
- B2. While a member is live, only instructions in borrow_safe run; a DECREF #0 in range is never of a container on the chain; any store to a list, any call, any helper that runs Python or releases containers, and any DECREF #1 end every borrow live across it.
- B3. Wherever unlocked_jit is 0 (every publish: published calls and helpers, TRUTH, DECREF #1, the stores, parked slow paths of a counted LIST_ITEM, INLINE_LOAD's box path and the poll's work in place; a return's bare DECREF #1), no member is live: those instructions are outside borrow_safe, or (POLL, INLINE_LOAD) leave the unit on that path while a member is live across. DECREF #0's slow path calls without publishing. So no second task can start while a borrowed value is live, and an exit never takes references to what one freed.
- B4. An exit owns exactly what INS_OWNED marks in its state and takes a new reference to every other slot value; an entry value is released only after all entry checks passed, and no state after its release names it, so nothing is released twice.
- B5. Every exit an entry check takes is a counted guard failure; past the usual threshold the entry pc is NOBORROW and the rebuilt unit counts those webs from the entry. No exit can repeat at every back edge uncounted.
- B6. Nothing is released earlier or later than CPython releases it: an entry reference goes only where its holder keeps another, and a member's release is removed only where its holder outlives the member's range.
