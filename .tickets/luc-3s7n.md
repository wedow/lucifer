# jit: stay in compiled code (keyword and star calls bound at compile time, exceptions as control flow, cells as loads, small polymorphic sites inlined)

Measured idiom rows that leave compiled code and run at or below CPython's speed: f(j, c=i) 530 cycles (PyPy 12), forwarding f(*args, **kw) 1418 (8), an exception raised and caught in the same function 1509 (37; a deopt and interpreter run per raise), isinstance(b, (C, B)) 210 (8; a tuple built and released per test, then a C subtype walk), a closure call 66 (4; each cell read is a C call), a call over three receiver classes 178 (21; a helper call and a full return instead of three guarded inlines), sum(genexpr) 268 per 100 items (39). In real programs the call path outside units (lu_jit_direct, call_argv, lu_jit_run, h_call, frame push/pop) is about 5% of steady state and type_lookup 2.8%.

Stages, one landing each, each gated on its idiom rows:
1. Calls: a call whose target is a known Python function binds positional, keyword, default and star parameters at compile time and inlines or calls the unit directly; no dict, tuple or frame is made.
2. Exceptions: a raise whose handler is in the same unit (after inlining) is a jump to the handler with the exception object made only if the handler reads it; a prim that fails inside a try reaches the handler without a deopt.
3. Cells: a cell read or write is a load or store on the cell object.
4. Polymorphic sites: a site with 2-4 receiver classes inlines each under its guard.
5. isinstance and issubclass against constant classes or a tuple of them fold to class guards.
6. Generator expressions and comprehensions consumed in the same unit run as loops.

Acceptance: each row within 3x of PyPy when its stage lands (1.5x is the epic's bar); jitcheck lanes for each shape.

**Stage (b) rule (before code).** A failing operation F whose innermost handler H in the unit (after inlining, the frames between kernel ones) is reached becomes a branch to H with its exception E a virtual object (VK_EXC: class, args, and the raising instruction's frame and lasti for its traceback entry) when:
1. E's class is known at compile time: an explicit raise of a constant class with BaseException's own construction (plain_class) and constant or side-effect-free args, or a producer that reports its miss as a value (a dict probe miss on an exact dict, an index past an exact list/tuple/str's size, an attribute lookup that misses on a guarded layout with no __getattr__, an exhausted exact list/tuple/range iterator).
2. H matches E's class at compile time: CHECK_EXC_MATCH against a constant class or tuple of constant classes read from guarded globals/builtins, or a bare except; anything else (a non-class, a computed tuple) is a run-time match and E is made.
3. Nothing reads E before it would be made anyway. The virtual E is made, with its traceback entry and the exc_info push PUSH_EXC_INFO skipped, at the first point that could observe it, which the build sees as it builds H: a STORE of E (an `as` name), RERAISE or a bare raise, a RAISE_VARARGS (which would chain E as __context__), a YIELD_VALUE/SEND/await, a helper that can run Python or C that reads exc_info (FX_PY or FX_SEEN: any call left out of line), and every exit (deopt) from the handler, whose description names E like any virtual and makes it, enters it in the traceback at its recorded lasti and sets exc_info as PUSH_EXC_INFO would have. Instructions that run no code (loads, constants, stack moves, int/float arithmetic on known types, STORE_FAST of other values, jumps) do not observe it. POP_EXCEPT of an unmade E restores nothing (exc_info was never pushed).
4. Otherwise (a class not known, a run-time match, a generator frame on the way) E is made at F exactly as today.
This replaces drops_unseen's fixed allow-list (loads and stack moves only) with "materialized at first observation", the same rule other virtual objects follow.
